# Phase 5AG — Official Sequence Name Reconciliation

## Purpose

Compare the 82 residual unmatched historical stop rows from Phase 5AA with the individual SMTA route-detail sequence entries captured in Phase 5AF.

## Method

- Rebuild Phase 5W and Phase 5AA from committed source data in GitHub Actions.
- Compare within the same route code only.
- Exclude the first numbered Phase 5AF direction descriptor; compare named entries only.
- Accept exact normalized name matches and explicit Phase 5Y user-confirmed spelling aliases only.
- Preserve multiple same-route matches as ambiguous rows; do not choose one automatically.
- Keep unmatched rows in the output.
- Do not accept fuzzy similarity scores, nearest nodes, proximity, or coordinate evidence as a name match.

## Outputs

- `data/research/PHASE_5AG_OFFICIAL_SEQUENCE_NAME_RECONCILIATION.csv`
- `data/research/PHASE_5AG_OFFICIAL_SEQUENCE_NAME_RECONCILIATION_REPORT.json` (workflow artifact)

The CSV is generated by the workflow and retained as an artifact; source historical registers are not overwritten.

## Interpretation limits

A name match does not prove a physical passenger stop, exact boarding pole, carriageway side, route direction, or current dispatch. Every output row remains `physical_stop_verification=unverified`, `coordinate_assignment=not_assigned`, and `route_approval_status=not_approved`.

No coordinates or OSM node IDs are copied into the output. No route geometry or database writes are performed.

## Known source conflicts

The route-detail vs route-map index discrepancies documented in Phase 5AE/5AF remain open, including R2/R3 origins, R11 endpoints, R12 origin, and R14's omission from the short map-index list. A sequence name match does not resolve those conflicts.
